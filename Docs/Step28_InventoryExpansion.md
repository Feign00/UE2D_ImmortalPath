## 五类背包

按 `I` 或 HUD“背包 [I]”打开 1600×300 横条界面。背包现在包含五个稳定分类：

1. 装备：使用原有 30 格容量，支持穿戴、锁定、整理、出售和分解。
2. 材料：独立堆叠，不占装备容量。
3. 丹药：按丹药 ID 与品质独立堆叠，不占装备容量。
4. 法宝：独立实例库存，不占装备容量，可在背包锁定；培养仍使用 `F` 界面。
5. 任务物品：独立堆叠，不占装备容量，不可出售或分解。

内置任务物品目录：

- `QingyunTrialJadeSlip`：青云试炼玉简，最大 99。
- `AncientMapFragment`：残缺秘境图，最大 99。
- `DemonKingSeal`：妖王印记，最大 999。

后续任务系统可通过 `/Game/GAME/Data/DT_QuestItems` 增加数据表行，无需修改背包结构。

## 整理规则

装备使用确定性顺序：

`锁定优先 → 部位 → 品质降序 → 等级降序 → 战力降序 → 名称 → GUID`

法宝使用确定性顺序：

`已装备优先 → 锁定优先 → 品质降序 → 星级降序 → 等级降序 → 名称 → GUID`

连续执行整理不会继续改变顺序。读档时也会修复无效实例、重复 GUID 和重复装备位；重复装备位中的独立有效物品会移回背包，不会静默删除。

## 锁定保护

装备和法宝实例新增持久化 `bLocked` 字段。锁定装备具有以下保护：

- 单件出售拒绝处理。
- 批量出售跳过。
- 单件分解拒绝处理。
- 批量分解跳过。
- 满背包自动替换时跳过。
- 已穿戴装备不会被更强掉落、打造品或百宝阁购买品自动替换。
- 百宝阁出售列表显示“已锁定”并禁用操作；业务层仍会再次验证，不能绕过 UI。

界面使用“锁”标识。锁定、解锁、整理、出售和分解都在 SaveGame 写盘成功后才提交；写盘失败会恢复原状态。

## 批量出售

品质筛选按“最高处理品质”工作，例如“≤稀有”只处理普通、优秀和稀有装备。已穿戴、已锁定和超过阈值的装备不进入集合。

批量出售复用百宝阁装备回收价，将所有符合条件物品和灵石增量作为一次事务提交。以下情况不会删除装备：

- 没有符合条件的装备。
- 灵石总额将超过 `MAX_int32`。
- SaveGame 写盘失败。

单件和批量出售均需要二次点击确认。挂机期间如果装备背包发生变化，确认态会自动失效并要求重新确认；单纯拾取灵石不会干扰确认。

## 装备分解

分解产物使用固定公式，避免重复加载时重新随机：

- 矿石：`1 + floor((装备等级 - 1) / 10) + floor(强化等级 / 3)`
- 灵铁：优秀及以上为 `品质序号 + floor(强化等级 / 5)`；普通为 0。
- 法宝碎片：史诗为 1，传说为 2；更低品质为 0。

材料先写入候选副本，只有每一种材料都能完整进入堆栈时才提交。因此材料上限不会造成“装备已经消失、材料只收到一部分”。SaveGame 失败时装备和全部材料一并回滚。

## 满包与打造安全

- 30 件全部锁定时，新装备不会覆盖任何一件物品。
- 混合满包时，即使锁定装备战力最低，也只替换实际最弱的未锁装备。
- 打造装备时会先验证装备位、空格和未锁替换候选；无法安全存放时按钮不可用或返回明确失败结果。
- 打造的材料、灵石、背包、穿戴、生命、法力、掉落计数和修订号属于同一事务。
- 打造品自动穿戴改变攻速时，会重新启动正在运行的自动攻击计时器。

## SaveGame v16

新增持久化字段：

- 装备与法宝 `bLocked`。
- `QuestItemInventory`。
- `bInventoryManagementInitialized`。

使用开发测试参数生成的受控 v15 fixture→v16 实机迁移结果：

- 30/30 背包装备 GUID 全部一致。
- 5 件已穿戴装备 GUID 与装备位全部一致。
- 2 件法宝实例 GUID 全部一致。
- 7 类材料 ID 和数量全部一致。
- 迁移后再次启动不重复迁移，锁定和任务物品状态保持。

迁移使用一次写盘提交；失败时保留待迁移状态，不会假装升级成功。
