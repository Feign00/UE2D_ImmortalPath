# 44：R04 退出保存失败保护

日期：2026-09-24。依据 `D:\ARPG\仙途项目现状与改进清单_2026-09-22.md` 的 R04。本阶段只处理菜单“保存并退出”、桌面窗口关闭请求和 Alt+F4 对应的系统关闭路径；不扩展玩法或美术范围。

## 改动

- 独立游戏的主窗口在销毁前接入可取消的关闭请求。窗口关闭按钮和 Alt+F4 对应的系统关闭消息改走与菜单相同的保存入口；保存失败时取消关闭，保持游戏可见。
- 新增退出保存失败提示，提供“重试保存并退出”“继续游戏”和需要二次点击确认的“跳过保存并退出”。提示覆盖在透明桌面战斗条上，不暂停后台战斗与修炼。继续游戏恢复输入；明确选择跳过保存后，`EndPlay` 不再补写一次存档。
- 成功退出仍先隐藏透明窗口，再解除色键/销毁窗口，沿用此前退出粉色闪屏的保护顺序。存档恢复锁定状态仍使用既有安全退出路径。无法拦截的关闭仅在 `EndPlay` 尝试兜底保存，失败会记录错误，不能反过来取消进程结束。
- 加入非 Shipping 的隔离目录运行夹具、失败注入和 UI 状态测试。两个原有超长日志格式调用拆成较短的等价日志，用于降低此巨大 C++ 编译单元触发的 MSVC 内部错误概率；玩法数据未改变。

## 已知限制与后续

- 故障夹具通过菜单接口、`WM_CLOSE` 和 `WM_SYSCOMMAND/SC_CLOSE` 覆盖同一关闭链路，并非人工实际按键；按钮逻辑有自动化测试，原生鼠标逐个点击、不同 DPI 与桌面前景合成仍需后续实测。不能把源截图当作真实桌面合成截图。
- 失败提示不暂停游戏。此次写入失败的瞬间原有主档与备份保持不变，但后台修炼可能稍后触发正常自动保存；界面明确告知此事。“跳过保存并退出”只表示退出时不再写入，不能撤销已经发生的后台自动保存。
- Windows 进程强制结束、断电、操作系统异常关闭和 Shipping 发行包不保证可拦截；仍依赖既有存档检查点与备份降低损失。保存成功也不是断电级文件事务。
- 构建中多次出现位置不固定的 MSVC C1001，链接器也两次出现 LNK1000；一次构建工具在打印并发数后提前结束。失败链接有时留下不完整的生成文件，不能把随后仅执行 `WriteMetadata` 的“成功”当成有效构建；最终重新触发实际编译和链接后，两个目标均通过。一次菜单正常退出运行在夹具开始前的引擎初始化阶段访问冲突，随后同一隔离目录重试通过。根因未查明，不能将其视为已修复，也不能归因于本阶段代码而无证据。
