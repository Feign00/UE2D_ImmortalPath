# 43：R02 普通地图击杀的一次性进度提交

日期：2026-09-24。依据 `D:\ARPG\仙途项目现状与改进清单_2026-09-22.md` 的 R02。本阶段只处理普通地图击杀及其关卡、任务、宗门和灵宠进度；世界妖王、无尽副本与其独立奖励事务未改。

## 改动

- 刷怪器先构造下一份地图状态，不提前改变关卡或显示通关。玩家把地图、任务、宗门和归属玩家的灵宠击杀经验合并到一次 `SaveToDisk`；成功后才更新刷怪器状态和胜利提示，失败则回滚玩家状态。
- 保存失败的普通地图怪物保留死亡表现，但跳过专用奖励蓝图回调，以及 C++ 装备、灵石和材料实体生成。普通死亡通知 `BP_OnMonsterDied` 仍会调用，不能在其中另行发放奖励。
- 去掉刷怪器在 `EndPlay` 的重复地图单独写入。击杀、切图与其他主动进度操作已在各自提交点保存；退出时再单独保存地图既不能解决前述两次写入问题，也曾出现在一次隔离重启测试的世界拆除阶段崩溃调用栈中。崩溃根因尚未单独确认。
- 增加仅非 Shipping 可用的“第 N 次逻辑写入失败”开关和计数器、随机隔离槽位自动化测试，以及限定 `Saved/Automation/MapCombat/<测试名>` 目录的真实演员测试入口。
- 为无预编译头编译补齐两个旧文件的显式头文件引用；玩法未改变。

- UE 5.7.4：`ImmortalPathEditor Win64 Development` 与 `ImmortalPath Win64 Development` 均编译、链接通过。最终使用 `-DisableUnity -NoUBA -NoPCH`；Game 最后一次增量编译使用单并发。
- 完整 `ImmortalPath.` 自动化：**68 成功、0 警告、0 失败、0 未运行**，报告位于 `Saved/TestReports/MapCombatR02FullFinal/index.json`。新增 `ImmortalPath.Save.MapCombatLogicalWriteFailure` 验证 N=1/N=2、主档与备份字节不变、四类进度同代读取。
- 真实怪物在青云山四种边界分别以 N=1 和 N=2 验证，共八组“击杀→退出→重启”：普通击杀、1 关 9/10 跨关、10 关 Boss、999 关最终 Boss。每组首次击杀与重启审计均通过，游戏进程退出码为 0。日志保存在 `Saved/Automation/MapCombat/<case>Fail1RootRetry/{First,Restart}.log` 与 `<case>Fail2RootFinal/{First,Restart}.log`；Boss N=2 重启首次在引擎初始化阶段崩溃，随后同一隔离档的 `RestartRetry.log` 通过。
- N=1 时每场景只尝试一次保存、原存档字节不变、地图/任务/宗门/灵宠内存均回滚、实体掉落增量为 0；额外普通保存后再重启，进度仍一致。N=2 时每场景仍只尝试一次保存，第二次失败开关未触发；进度和奖励正常，重启后的战斗字段一致。

## 测试中发现与剩余边界

- 首次跨关重启测试间隔超过一分钟，离线修炼正常提升境界，令任务状态的无关版本号变化。测试已改为重启时只比较战斗拥有的字段；首次击杀前后仍比较完整状态和原始存档字节。此处是测试误判，不是跨关漏记。
- 构建过程中 MSVC 多次在不同、未修改的引擎模板处报告 C1001，Clang 的引擎预编译头也曾崩溃；关闭预编译头后两目标通过。另有两次游戏逻辑开始前的引擎初始化/素材加载崩溃，隔离重试通过。上述间歇异常的根因未查明，不应把本阶段通过等同于发行环境稳定性已验收。
- 本阶段保证一次击杀相关进度处于一份逻辑存档，不能把 UE 的普通主档覆盖写入称为断电级文件原子性；R01 的上一份备份保护仍在。成功提交后、实体掉落生成前若进程突然终止，实体掉落也不具备跨进程的恰好一次保证。
- Boss 召唤小怪只记录任务/宗门击杀，世界妖王与无尽副本使用既有独立流程，不属于本次普通地图事务。透明窗口中的失败提示尚未做原生视觉/点击验收；本次测试为真实演员、存档字节和重启状态验证。
- `BP_OnMonsterDied` 为通用死亡通知，在失败路径仍播放；当前没有证据表明已有蓝图在此发放奖励，但将来新增蓝图时必须遵守“奖励只从专用奖励回调或成功提交后生成”的约定，否则需扩大失败抑制范围。
- Shipping Cook/打包、长时间挂机、显示环境矩阵与偶发初始化崩溃仍待 R11/R12。下一独立部分按清单处理 R04：菜单与系统窗口关闭时的保存失败保护，特别是可拦截关闭与不可拦截强制终止的边界。
